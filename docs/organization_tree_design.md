# 组织机构树

HuRAG针对大型组织机构用户设计，对组织内所有机构和用户进行统一管理。组织机构树用于表示组织的层次结构，每个节点代表一个机构，节点之间的连接表示机构之间的隶属关系。每个用户在组织机构树中有一个位置，这个位置决定了用户可以访问和检索哪些文档。

## 组织机构的表示

组织机构树采用树形结构表示，根节点代表最高级别的机构（如公司总部），子节点代表下属机构（如各个部门、分公司等）。每个节点包含以下信息：

每一个机构采用类似文件目录树的表示方法，用斜杠分隔各级机构名称，例如：

`/公司总部/某省公司/某市分公司/某区办事处`

作为根机构的公司总部，其路径为 `/公司总部`。所有组织内部机构的路径均以根机构路径开头，前置 `/` 符号。

## 文档的发布机构

文档发布机构使用全路径表示，例如某省公司发布的制度文件，其发布机构为：`/公司总部/某省公司`，与组织机构树中的节点路径一致。

如果文档的生效范围包括发布机构及其所有下属机构，则在发布机构路径后添加通配符 `*`，例如上述制度文件的发布机构可表示为：`/公司总部/某省公司*`。

某些文档，例如国家法律、政府政令等，并非组织内部发布，此类文档的发布机构可设为特殊根机构，常见的有 `全国人大常委会`、`国务院` 等，表示该文档适用于所有组织用户。此类机构路径前无前置的 `/` 符号，路径后也无需添加通配符 `*`，默认在整个组织范围内所有机构生效、可查阅。

## 用户的机构位置

每个用户在组织机构树中有一个位置，表示该用户所属的机构。例如某市分公司法务部的用户，其机构位置为：`/公司总部/某省公司/某市分公司`。

用户的机构位置决定了其可以访问和检索的文档范围。用户可以访问其所属机构及其所有上级机构发布且向下生效的文档（即上级机构发布且发布机构以通配符 `*` 结尾的文档），同时用户可访问所有非组织内部发布的文档（如国家法律、政府政令等）。

例如上述某市分公司的用户，可以访问以下发布机构的文档：
- `/公司总部*`
- `/公司总部/某省公司*`
- `/公司总部/某省公司/某市分公司*` 或 `/公司总部/某省公司/某市分公司`
- `全国人大常委会` 或其他此类外部全局文档

## 用户认证及机构位置确定

HuRAG作为面向组织型用户的应用，其用户的认证及其所在机构位置的确定通常建议采用组织内部已有的身份认证或单点登录系统进行集成。通过集成现有的身份认证系统，HuRAG可以自动获取用户的机构位置，从而实现基于机构位置的文档访问控制和检索功能。

HuRAG将在其子项目 `hurag-webui` 中提供与常见身份认证系统集成的示例和指南，帮助组织用户快速实现用户认证及机构位置的确定功能。一般可通过以下几种方式集成：
- LDAP/Active Directory 集成
- SSO（单点登录）集成
- 组织内部用户数据库集成
- 组织内部其他应用授权，通常建议由 OA 或 HR 系统授权
- hurag-webui 提供的插件化简易认证模块

无论采用何种方式集成，关键在于确保 HuRAG 能够准确获取每个用户的机构位置，且与知识库中文档的发布路径保持一致，以便实现基于组织机构树的文档访问控制和检索功能。最少需要获取的信息包括：
- 用户唯一标识（如用户名、用户ID等）
- 用户登录账号
- 用户真实姓名
- 用户所属机构的完整路径（如 `/公司总部/某省公司/某市分公司`）

若使用 `hurag-webui` 提供的插件化简易认证模块，则可在配置文件中直接为每个用户配置其机构位置、账号、姓名。 *注意：该模块仅提供免密登录，并非安全的认证方式。*
